# Clean-sheet：独立评审协议的重新设计（5 套竞争方案 + 对抗场景对照）

> **这份文档不是当前"轮次认证"框架的 V2。** 它接受一次**问题重新定义**，然后从零设计若干协议，再用同一组对抗场景比较。
>
> **问题重新定义（接受）**
> 旧：**"怎样证明这一次评审是在独立的新上下文里执行的？"**
> 新：**"怎样以最低边际成本，持续获得足够可信、可复现、可审计的独立挑战信号，而且不依赖某个平台的执行机制？"**
>
> 一旦这样定义，`fresh context` / `execution receipt` / `round certification` 就**只是众多手段之一**，不再属于方法论核心。
> 本文的目标是把这句话变成一份可比较、可实现的协议清单。

---

## 0. 为什么这个重新定义是**对的**：本仓库自己的数据

| 证据 | 说明它推翻了什么 |
|---|---|
| **确定性检查抓到 ≥11 处"能恒真的检查"，而"读代码"抓到 0 处** | **`fresh context` 买不到多少东西**；买得到的是"可执行的反例" |
| **多轮记录中 65%–90% 的 finding 是关于上一小时的修复** | 新鲜上下文**不妨碍**同类盲点重演（同一模板、同一分布） |
| **62 轮中 28 轮零记录；同一个 revision 上 4 次派发 0 条可接受记录** | "证明过程独立"这条路**连自己的产物都收不回来** |
| **某 change 的 judge 在其审查轮通过后 11 分钟被兄弟修复作废** | **认证绑定内容**这个设计，使"轮次"成为成本的放大器 |
| **最贵两轮（874K / 658K tokens）产出为零；有数字期限的轮次 134K–216K / 3.4–7.7 分钟** | 过程越长 ≠ 质量越高，**成本与价值近乎无关** |

**结论**：`fresh context` 是一个**代理指标**，而它代理的东西（不被既有结论锚定）**既非必要也非充分**。
真正有信息量的是**输出端的惊喜**：一个**此前未被提出、可执行、可复现**的攻击路径。

> **⇒ 认证对象从 `execution provenance` 转向 `epistemic contribution`（认识论增量）。**

## 1. 我们真正需要保证的性质（clean sheet）

### 需要（7 条）

| # | 性质 | 精确表述 |
|---|---|---|
| **N1** | **假认证不可能** | 任何被认证为"成立"的 claim，必须携带**一份能失败的证据**（变异、反例、挑战测试之一）；没有能失败的东西，就不算被认证 |
| **N2** | **可复现** | 第三方仅凭 `artifact_digest + 记录` 就能重现**每一条被采纳的 finding**与**每一条认证** |
| **N3** | **有界成本** | 成本是变更规模与风险的**声明函数**，并且**可观测**（不是自报） |
| **N4** | **可离线审计** | 认证是一份**持久记录**，后来的第三方可在不看会话的情况下复核 |
| **N5** | **平台无关** | 认证要求**只引用产物与执行**，绝不引用会话/上下文/进程事实 |
| **N6** | **增量** | 变更**只重开它影响到的 claim**（这是消灭"修复作废整轮"的关键） |
| **N7** | **反例优先** | 一条可执行反例 > 一份详尽报告；散文不构成证据 |

### **不需要（可以删除的现行要求）**

| 删掉的 | 为什么它不再是一条性质 |
|---|---|
| 证明"上下文是新的" | 代理指标，N1/N7 已覆盖它想要的实质 |
| 证明"谁审的" | 单机场景没有问责对象；要问责就用 N2（可复现）而非身份 |
| 证明"审了多久 / 用了多少工具" | 成本项，不是安全项（保留为**可观测**即可，N3） |
| "所有 finding 都被处置" | 开集；替换为 **"无未解决的高严重度反例"**（一个状态） |
| "覆盖每一条路径/每个判据" | 开集且不可判；替换为 **"规定的风险类别都经过独立挑战"**（一个有限集） |
| `session` / `thread` / `fresh chat` / `conversation id` / `platform execution receipt` | **全部降级为 provider-specific 的可选 attestation** |

## 2. 五套竞争协议

> 每套给出：**单元 / 输入输出 / 认证规则 / 它能做到什么 / 它的失效模式**。全部满足 N5（平台无关）。

### 协议 A — **Claim Ledger（取消"轮次"）**

**单元是 claim，不是 revision。** 变更不再触发"新一轮"，而是重开**受影响子图**。

```
Claim
├─ statement            "C17：修复 X 后不影响已认证的安全性质 Y"
├─ evidence[]           可执行证据：selector 跑绿 + 一个让它变红的变异
├─ challenges[]         针对它的反例/挑战测试（可执行，失败即未解决）
├─ risk_class           假设 / 边界 / 状态迁移 / 权限 / 失效模式 / 回滚 / 并发 / 来源 / 依赖
├─ depends_on[]         该 claim 依赖的 artifact 摘要与其它 claim
├─ status              open | challenged | refuted | certified | waived(带理由)
└─ provenance           可选：谁产出的（不参与判定）
```

**变更流程**：改动 artifact ⇒ 计算**影响集**（依赖闭包）⇒ 只重开影响集内的 claim ⇒ 要求 ① 证据重跑为绿 ② 高风险 claim 每个必须有**规定风险类别的至少一次独立挑战** ③ **影响集内没有未解决的反例**。

- **认证 = 账本的影响集是干净的**（一个**状态**，不是一个过程）✓
- **买到**：N6 增量（成本 ≈ 影响面 + 抽样，而不是"整篇 × 轮数"）· **"修复作废整轮"这个问题直接消失**（重开的是 claim，不是轮次）· 终止条件变成可判的状态 ✓ · 无 session 概念 ⇒ **零平台耦合** ✓✓
- **失效模式（新的一类，必须承认）**：**依赖图保真度** —— 边错 ⇒ 影响集错 ⇒ 某个变更悄悄躲过重验。
  缓解：① **保守过近似**（宁可多开）；② 派生不出的依赖退化为**整个模块**；③ **抽样复核**：随机挑一条**已 certified 且与本次变更无关**的 claim 重验，用它的失败率度量图的保真度 ✓

### 协议 B — **Counterexample Bounty（反例悬赏，含挑战–应答）**

**审查者不交报告，只交反例**；每条反例必须**两侧成立**：

```
counterexample
├─ fails_on       缺陷存在的 revision（必须是当前/声明的那个）  → kata 跑，必须红
├─ passes_on      修复后的 revision（或"所声称已修复"的）        → kata 跑，必须绿
├─ targets[]      攻击的 claim / 风险类别
└─ command        一条 kata 能独立执行的命令
```

**两侧**是关键增强：今天的 `falsify` 是单侧的（变异→红），**它不检查"修好了没有"**；两侧成立才证明"这个反例描述的正是那个缺陷，且修复真的消除了它"。

**挑战–应答（E）**：kata 可以**事后随机出题** —— 从账本里随机抽一条 claim，给一个预算与期限，要求提出反例。**审查者历次应答的成功率，取代了凭据** ✓
- **认证 = 应答率 + 反例两侧成立**；**"你在哪跑"完全退出判定** ✓✓
- **买到**：零信任过程 · 产物是文件 + 退出码 ⇒ 解耦最彻底 · 空产出 = 没有反例 = 无事发生（而不是"一份看起来完整的报告"）✓
- **失效模式**：① **引导期**（首轮没有历史应答率）⇒ 用已知缺陷语料播种；② 只交"小而真但无价值"的反例 ⇒ 按**风险类别的多样性**计分，而非条数；③ 出题可被预测 ⇒ 出题种子记录在案且**按类别分层抽样**

**与现行规则的冲突及解法**：仓库现行规则是"Review 不得编写测试"。**解法**：反对例**落在产品测试套件之外**的独立位置（`challenges/`），**在作者采纳之前不构成认证证据** ⇒ 角色分离保住了，而反例仍可执行 ✓

### 协议 C — **Risk-Adaptive Sampling（风险自适应 + 抽样审计）**

按**确定性风险分类器**（触达路径、类库增量、claim 严重度、该文件的历史缺陷密度）选**深度档**：

| 档 | 要求 |
|---|---|
| **T0** | 只有确定性检查（零 token） |
| **T1** | 一次廉价挑战（预算小、窄范围，带数字期限） |
| **T2** | k 个独立审查者 + **风险类别全覆盖** |
| **T3** | 人类签字 |

**抽样审计（统计过程控制）**：按**记录在案的随机种子**，把一小部分 T0/T1 **事后升格**为 T2；升格失败率就是**分类器自身的误差信号** ⇒ **分类器被测量，而不是被信任** ✓
- **买到**：成本随抽样率下降而**完整性可统计** · **保住 `strict` 档的含义**（重流程仍存在，但作用于样本）· 全部在 kata 内部 ⇒ 解耦 ✓
- **失效模式**：分类器博弈（把一切标为低风险）⇒ 用升格失败率作为公开指标；**阈值由人设定**

### 协议 D — **N-Version Differential（多版本差分）**

同一 artifact 交给 **k 个互不知情**的审查者（不同 provider / 模型 / 提示模板），比较输出：

```
确认 = 被 ≥2 个审查者独立提出的 finding          → 自动采纳
可疑 = 只被 1 个提出                              → 升级复核
多样性 = hypothesis 集合的两两重叠率              → 低于阈值才算"独立"；过高则判为冗余并拒绝计费
```
- **买到**：**唯一直接测量独立性（而非断言）的设计** —— 通过**输出端的多样性** ✓ · 统计意义上回答遗漏：k 个都漏的概率随独立性的真实程度下降 ✓
- **失效模式**：成本 ×k；"互不知情"仍需平台保证（**除非**用不同 provider 且不共享提示）；多样性低到阈值以下时它退化为一份昂贵的冗余

### 协议 E — **Human-Anchor（人签字为认证）**

机器只产**候选**：反例 + 风险类别覆盖表 + 未解决反例清单。**认证 = 人签的一次决定**，而 `review_gate` **本来就存在且本来就由人完成**。
- **买到**：**解耦的最强形态**（人的独立性不来自任何平台）· 成本低（人读 5 条反例 + 一张覆盖表）· 与现行治理一致（人本来就持有这个决定）✓
- **失效模式**：橡皮图章 ⇒ 要求人对**随机抽取的一条争议反例**作出裁决（**E 用在人身上**），并把它记入审计

## 3. 对抗场景对照（同一组场景，看每套协议能不能挡住）

| 场景 | 含义 | A 账本 | B 悬赏 | C 自适应 | D 多版本 | E 人签 |
|---|---|---|---|---|---|---|
| **S1 装饰性检查**（能恒真的检查进入认证） | 本线实测 11 处 | **挡**（证据必须能变红） | **挡**（反例必须能红） | **挡**（T0 就要求变异） | 弱（可能都被同一诱因骗过） | 中（人要能看到"这条证据能失败吗"） |
| **S2 伪造反例**（在别的 revision 上红、这里绿） | 门必须能识破 | **挡**（两侧绑定 digest） | **挡**（fails_on 绑定当前 digest） | 挡 | 挡 | 弱（人可能看不出） |
| **S3 遗漏**（缺陷落在无人挑战的区域） | 逻辑上不可证 | 弱（风险类别覆盖是部分答案） | 弱 | 中（抽样升格） | **中～强**（k 重独立） | 中 |
| **S4 自证测试**（审查者写一条弱测试） | 现行规则禁止写测试 | 不适用 | **挡**（两侧 + 作者裁决） | 中 | 中 | 中 |
| **S5 假修复**（改了代码但缺陷仍在） | 反例两侧不成立 | **挡**（证据重跑） | **挡**（passes_on 必须绿，失败即假修复） | 挡 | 挡 | 弱 |
| **S6 依赖图漏边**（修复影响别的 claim 而未被重开） | **A 特有的新风险** | **弱（需抽样复核）** | 中 | 中 | 中 | 弱 |
| **S7 成本失控**（一轮烧 1.2M tokens 却零产出） | 本线实测 | **强**（增量） | **强**（有界预算） | **强**（按档） | 弱（×k） | 中 |

**读法**：**没有一套挡住全部**。B 在 S1/S2/S4/S5 上最强，A 在 S7 与终止性上最强，D 是唯一对 S3 有实质作用的，E 是最便宜且唯一在人身上成立的。

## 5. 推荐组合与最小实验

### 推荐：**B + A + E（+ C 作为成本闸门）** —— 暂称 **Outcome-verifiable Independent Review**

```
① 单元：claim 账本（协议 A）             → 增量，取消"轮次"，终止条件可判
② 证据：两侧成立的可执行反例（协议 B）    → 认证靠执行，不靠过程
③ 出题：事后随机挑战 + 应答率（B 的 E 部分）→ 用【能力记录】取代【凭据】
④ 认证：人签一次决定（协议 E）            → 平台无关的独立方，且 gate 已存在
⑤ 闸门：风险自适应深度 + 抽样升格（协议 C）→ 成本有界、完整性可统计
```

**它明确保留的四条判据（对应最初的四个认证对象，但都改成了"结果属性"）**

| 原来的认证对象 | 在这个方法论里 |
|---|---|
| 输入边界（reviewer 被允许看到什么） | **降级为可选元数据** —— 这是四个里**唯一仍在描述过程**的一项；结果可验的协议不需要它 |
| 挑战能力 | **可测**：随机出题的**应答率** + 反例的**新颖性**（不在已有 claim/证据图里的新攻击路径） |
| finding 可验证性 | **两侧执行**：缺陷 revision 上必红、修复 revision 上必绿 |
| 覆盖充分性 | **风险类别覆盖契约**（有限集，可判），不是"覆盖每条路径"（开集） |

### 最小实验（不写新架构，一天内可做）

| 实验 | 做什么 | 量什么 |
|---|---|---|
| **E1（最先做）** | 把某个 change 的 AC 从"有通过的证据"改为"**有一个会变红的变异**" | 零 token 下能多抓到什么？ |
| **E2** | 对同一 revision 跑：现状 / 现状+数字期限 / **只交反例（B）** | 每条被采纳反例的成本 · 漏检（用播种缺陷） |
| **E3** | 给 B 加**两侧**要求（fails_on / passes_on） | 假修复与伪造反例的检出率 |
| **E4** | 事后随机出题（E），记录应答率 | 应答率是否比"有没有凭据"更能预测**被采纳反例数** |
| **E5** | 抽样复核已认证且无关的 claim（A 的图保真度度量） | 依赖图的漏边率 |

**判定指标**沿用仓库已定的目标函数：
`minimize(tokens, latency) subject to criticalRecall ≥ baseline · falsePassRate ≤ baseline · reproducibility ≥ baseline`
**语料**：基准语料（历史缺陷 + 种子缺陷 + 变异 + 已知良好 revision）——**没有它，§4 的比较只能是印象**。

## 6. 与现行架构的关系（哪些留、哪些删、哪些是新风险）

| 现行组件 | 处置 |
|---|---|
| `falsify`（反例账本，记 `{before, mutated, after}`） | **留并升级**：加"两侧"（fails_on / passes_on），升为认证主路径 |
| 类表 + 覆盖检查（`roundMayClose`） | **留**，并入协议 A 的 claim/风险类别状态 |
| `adversarial record` + 覆盖协议 + gate 条件表 | **大减**：协议 A/B 下不再需要"覆盖清单 + 记录 schema"这套簿记；报告式只作为**发现新类**的载体保留 |
| 轮协议（流式、能力反驳、凭据、登记表） | **降级为可选 attestation**（想留过程级证据的人可以用） |
| 只读 / 内容漂移观测 | **改造**：协议 B 下审查者会写（`challenges/`），改为"**写入范围限定 + 作者裁决**" |
| brief 内数字期限 | **留**（唯一有效的成本杠杆，实测 0/4 → 6/6） |
| **新风险：依赖图保真度**（协议 A） | **需要新的检查**：保守过近似 + 抽样复核（E5） |
| **新风险：分类器博弈**（协议 C） | 需要"升格失败率"作为公开指标 |
| **新风险：多样性阈值**（协议 D） | 若采用 D，需要一个可测的重叠率阈值，否则"独立"无从判断 |
