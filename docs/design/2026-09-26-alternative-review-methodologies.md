# 发散：能同时做到「评审质量 · 压缩成本 · 平台解耦」的其它方法论

> **状态：发散稿，不是决策。** 目的：把讨论从"当前架构之内怎么修"抬到"架构之外还有哪些做法"。
> 每条候选都写清 **机制 / 买到什么 / 代价与风险**，并在末尾给出**对照表**、**CCIS 综合方案**、**最小判定实验**。
> 所有与本仓库有关的数字都是实测；"新"标记表示这份发散稿才提出的方向，"已有"表示仓库里已存在或已提案。

## 0. 先钉住约束：任何方案都必须尊重的 8 条实测事实

| # | 事实 | 出处 |
|---|---|---|
| **F1** | **一轮的发现主要关于上一轮的修复**（四轮 23 条中 15 条 = 65%；另一批 21 条中 19 条 = 90%） | 本线多轮记录 |
| **F2** | **认证绑定内容；修复改变内容** ⇒ 修复使刚买到的那轮作废（实测：某 change 的 judge 在被接受 11 分钟后被兄弟修复作废） | `stale_revision` / `lane` |
| **F3** | **对"造机制的 change"，findings 不会降到 0**（十轮 `7,5,5,2,5,9,10,12,14,14`）；每处修复都新增表面 | 同 |
| **F4** | **LLM 作为"记录的生产者"不可靠**（62 轮中 28 轮零记录）；但 **brief 内的数字期限把它从 0/4 变成 6/6** | 对照实验 |
| **F5** | **确定性检查抓到的，比那一轮审查抓到的更多**：一天内 **≥11 处"能恒真的检查"全部由变异发现，无一由读代码发现** | 类表 + 变异验证 |
| **F6** | **最有价值的发现是"类级"的**（"某声明宣称的比它做到的多"），而不是实例级 bug | 类表 7 条 |
| **F7** | **成本口径是"每条被采纳 finding 的成本"**：最贵的两轮（874K / 658K tokens）产出为零；有期限的轮次 134K–216K / 3.4–7.7 分钟 | 轮次统计 |
| **F8** | **一轮的成本几乎全在"重新发现上下文"**（350–660K tokens/轮，而 brief 只占 3–6%） | 同 |

## 1. 十个候选范式

### P1（新）**确定性优先：检查即评审**
- **机制**：把"评审"从一次性会话，改成**一组持续增长、变异验证过的确定性不变量**。变更的判据不通过"有人审过"，而通过"所有相关不变量在此 revision 上为绿，且每条都能在变异下变红"。
- **买到**：成本≈机器时间（**零 token**）· 完全平台无关 · 可重复 · 抓到的是**已知类**的回归。
- **代价**：**它发现不了新类**。发现能力必须由别处提供。且不变量库本身需要设计，会像代码一样腐化。

### P2（新）**证书模型：作者产机器可验的证书，kata 验证书**
- **机制**：每个 AC 必须附一份**证书**：`selector`（跑它是绿的）+ **一个让它变红的变异**（kata 自己施加并观察）+ 它覆盖的**类**。kata 只做一件事：跑 selector → 施加变异 → 观察红 → 还原 → 观察绿。
- **买到**：**终止性**（证书有穷、检查确定）· **零 token** · **解耦**（kata 自己跑）· 而且比"审过一遍"强得多：**它要求判据可被证伪**，而不是要求有人读过它。
- **代价**：**Goodhart** —— 作者可以造一个"能变红但无意义"的变异。缓解：变异必须落在**被审查的语义**上（由类表约束），且 kata 可以补充**自己的**变异（基准语料）。
- **注意**：这与仓库已有的 `falsify`/AC matrix **同源**，但把它的地位从"辅助证据"提到"认证的主路径"。

### P3（新）**反例即产出：审查者交"会红的检查补丁"**
- **机制**：一轮审查的交付物不是报告，而是**一组会失败的检查**（或变异配方），每个都证明一个缺陷。kata 按**执行**判定：在当前 revision 上它确实红。
- **买到**：**自证**（反例在当下 revision 上失败，不需要覆盖协议来证明"它真的看了"）· **brief 可以小得多**（不需要 103 KB 的覆盖清单）· **产物是文件 + 退出码** ⇒ 平台无关 · **省报问题被削弱**：空产出 = 没有补丁 = 无事发生（而不是"一份看起来完整的报告"）。
- **代价**：**审查者开始写代码**，与仓库现行规则（"Review 不得编写测试"）直接冲突。该规则的理由是"审查者自写的测试可以很弱/自我服务"；**反制是变异 + 由作者裁决**（作者要么修，要么驳回这条反例）—— 这实际就是**测试的 pull request**。这不是小事：它改变了"审查者"的角色定义。
- **风险**：一轮可能只交 1 条反例（真实但狭窄）；需要"每类至少 N 条"之类的下限，否则质量靠运气。

### P4（已有，但可升为主判据）**库存模型：完成 = 类库存无缺口**
- **机制**：一个 change 的"完成"不是 "findings = 0"，而是**本 delta 涉及的每个类都有一条会红的检查**。
- **买到**：**终止条件可判**（本线已实现 `roundMayClose`）· 与 F3 相容（不要求 findings 下降）· 平台无关。
- **代价**：**发现新类仍然需要额外一轮**（新类没有覆盖检查 ⇒ 必须装一条 ⇒ 装检查是作者的活 ⇒ 新 revision ⇒ 找到它的那轮作废）。**这就是 F2 的循环在新框架里的原样复现** —— 必须正面承认，见 §4。

### P5（新）**探针群 + 确定性分流（把 review 当 fuzzing）**
- **机制**：不再"一轮大审查"，而是**许多小探针**：每个探针一个窄问题（"这个判据的选择器真的断言了它吗？"·"这个声明与代码一致吗？"），产出是一个布尔/一条证据；分歧由一个**确定性分流器**处理（一致⇒采纳，不一致⇒升级）。多样性来自探针的角度不同。
- **买到**：单探针的 prompt 极小（不必装 103 KB 上下文）⇒ **成本随探针数线性而非指数** · 每个探针可独立重跑（可复现）· 平台无关。
- **代价**：需要**探针库**（又是一份要维护的资产）；探针间的重叠会浪费；"谁来写探针"变成新问题（可由类表派生：**每个类派生一个探针**）。

### P6（新）**跨轮记忆：只记事实，不缓存判断**
- **机制**：给审查会话一份**持久的检查账本**（读过哪些文件、跑过哪些命令、得出过哪些事实），使下一轮不必从零重建上下文。
- **买到**：直接打击 **F8**（350–660K/轮 ⇒ 大幅下降）· 平台无关（一个文件）· 并且让"这一轮与上一轮的差异"自然浮现。
- **代价**：**锚定偏差**（记忆会把审查者锁进上一轮的框架）。缓解规则**本仓库已有**：`docs/verfify.md` 的原则 —— *缓存**事实**可以，缓存**判断**不行*。账本只存"我读了 X，X 的内容是 Y"，不存"我认为 X 有问题"。

### P7（新）**双轮独立 + 差异分析**
- **机制**：同一 revision 跑两轮**互不知情**的窄审查，比较两者**假设集合的差异**：只有一轮提出的假设被升级复核。
- **买到**：这是**省报（omission）的可检测近似** —— 单轮看不出漏，两轮的集合差异会暴露"这块区域只有一个人看"· 每轮可以很便宜（窄范围）。
- **代价**：成本翻倍；两轮都漏的情况检测不到；需要"独立性"至少达到"互不可见"。

### P8（新）**抽样严格审计（统计过程控制）**
- **机制**：**不要求每次都用重流程**；按**记录在案的随机规则**抽一部分 change（或一部分轮次）走**过程级**认证（凭据、隔离、完整包络），其余走**产物级**认证（证书 + 反例 + 类库存）。
- **买到**：**成本随抽样率下降**，而**完整性可统计**（审计覆盖率、抽中失败率）· 它**保住 `strict` 档的含义**（过程级认证仍然存在，但施加于样本而不是全体）· 平台无关（抽样规则与裁决都在 kata）
- **代价**：未抽中的变更只有产物级保证；抽样规则必须**不可被博弈**（种子记录在案、不得按内容选择）—— 否则会退化为"总是抽容易的"。
- **现实参照**：这与"代码冻结 + 抽查 + 事后审计"是同一族。

### P9（新，最便宜）**人类为认证者**
- **机制**：AI 轮次只产**候选**（反例 + 一句话），**认证由人在 `review_gate` 完成** —— 而这个 gate **本来就存在**，且本来就必须由人完成（kata 不配置/不路由宿主模型）。
- **买到**：**平台解耦的最强形态**（人的独立性不来自任何平台）· 成本低（人读 5 条反例，而不是读 103 KB brief）· 且与现行治理一致（人本来就持有这个决定）
- **代价**：**人的时间**；不一致（同一人不同时间不同标准）；不适合无人值守
- **关键洞察**：**我们为了解决"AI 审查者不独立"，一直在机制上替代人；而人在环里，且是人持有这个决定权。**

### P10（新）**为"被采纳的反例"付费**
- **机制**：激励与价值对齐：**一条被验证的反例 > 一份详尽的报告**。评审的"报酬"（或评分）只按被采纳的反例计；散文报告不计。
- **买到**：直接解决 **F4**（"不产出记录"变成"没有产出"而不是"一份好看的报告"）· 让 LLM 的**目标函数**与判据一致（可执行、可验证）
- **代价**：可能诱导"碎小、真实但无价值"的反例刷量。缓解：按**类的多样性**而非条数计，并要求每条反例覆盖的类没有被现有检查覆盖

## 2. 综合：**CCIS**（Certificate · Counterexample · Inventory · Sampled audit）

把上面最互补的四条组合成一条新主线（其余作为可选增强）：

```
① 证书（P2）     作者侧：每个 AC 带 selector + 会变红的变异 + 覆盖的类；kata 机械验证（跑绿→变异红→还原绿）
② 反例（P3）     审查侧：交付物是"会红的检查补丁"或变异配方，kata 按执行判定
③ 库存（P4）     完成条件：本 delta 的每个类都有会红的检查；不要求 findings 下降
④ 抽样（P8）     过程级认证（凭据/隔离/完整包络）按记录在案的随机规则施加于样本
可选：跨轮事实账本（P6）· 双轮差异（P7）· 人类仲裁（P9）· 按类多样性的激励（P10）
```

**为什么这四条会同时改善三个目标**

| 目标 | 由哪条买到 | 依据那些实测事实 |
|---|---|---|
| **质量** | ① 让判据**必须可被证伪**（而不是"有人读过"）；② 反例**自证**；③ 完成条件**可判**；④ 过程级诚信**仍然存在**（作用于样本） | F5（变异抓到 11 处而阅读抓到 0）· F6（价值在类级）· F3（findings 不降） |
| **成本** | ① 零 token；② brief 可大幅缩小（无覆盖协议）；④ 重流程只作用于抽样；可选 P6 直接砍掉 F8 的重建成本 | F7 · F8 |
| **解耦** | ①③④ 全在 kata 内部（跑命令、看内容摘要、判库存）；② 的产物是**文件 + 退出码**；P9 让"人"成为平台无关的认证者 | 本线实测：无 executor 时全流程卡住；子代理无归属字段 |

**关键的结构性变化**：**"审查一次"不再是质量的主要来源**，"检查库 + 证书"才是；审查轮从**认证者**降级为**候选发现者**（发现新类与新反例），而**认证由 kata 对证书/反例的执行完成**。这正是证明助手范式的字面应用：**模型提议，kernel 判定**。

## 3. 它没有解决什么（必须说清）

| 未解决 | 说明 | 谁能回答 |
|---|---|---|
| **新类的闭环仍要多一轮** | 新类 ⇒ 没有覆盖检查 ⇒ 必须装一条 ⇒ 装检查是作者的活 ⇒ 新 revision ⇒ 找到它的那轮作废（F2 循环原样存在） | 只能靠 **P4 的近似**（新类允许多轮累积后再判库存）或 **P7/P8**（抽样与差异降低"必须立刻闭环"的压力） |
| **省报仍不可检出** | 反例形态削弱了它（空产出 ≠ 完整报告），但没有消除 | **P7**（双轮差异）是唯一可检测的近似 |
| **证书可以被裁成刚好通过** | Goodhart | 基准语料里由 kata 自己补变异 · 抽样审计 |
| **P3 与现行"审查者不写测试"规则冲突** | 这是一次**立场变更**，不是修补（理由与反制见 §1 P3） | **需要你决策** |
| **质量提升仍是假设** | 上面每一条都是"应当更好"，而不是"实测更好" | **§4 的最小实验** |

## 4. 最小判定实验（怎么用数据而不是印象来选）

**同一个 revision，三种模式各跑 3 次**，比较四个量：

| 模式 | 交付物 | 预期 |
|---|---|---|
| **A 现状**（报告式 + 覆盖协议 + 凭据要求） | 记录 + findings | 基线：134K–1.22M tokens/轮；1–11 条 finding，多数为实例级 |
| **B 现状 + 数字期限 + 只用库口径**（本线已测） | 同上 | 记录产出率 0/4 → 6/6；3.4–7.7 分钟 |
| **C CCIS**（证书 + 反例补丁 + 类库存） | 会红的检查补丁 + 证书 | 待测：**每条被采纳反例的成本**、类覆盖的推进速度、以及"审查者写测试"的误报率 |

**判定指标（沿用仓库已定的目标函数）**：`minimize(tokens, latency) subject to criticalRecall ≥ baseline · falsePassRate ≤ baseline · reproducibility ≥ baseline`。
**语料**：已规划的基准语料（历史缺陷 + 种子缺陷 + 变异 + 已知良好 revision）—— **没有它，上面所有候选都只能靠印象比较**（这也是既有设计把 Phase 0 排在最前的原因）。

**先做哪一个**：不需要一次做完。**最小的一步是 P2 的"证书"**：把一个 change 的 AC 从"有通过的证据"改为"有会变红的变异"，看它是否在**零 token 成本**下抓出更多问题。这一步**不改审查流程**、**不动平台**、可在一天内对已有 change 试跑。

## 5. 与当前架构的关系

| 当前组件 | 在 CCIS 下 | 理由 |
|---|---|---|
| `falsify`（反例账本） | **升为主路径**（P2 的检查器） | 它已经记录了 `{before, mutated, after}` |
| 类表 + 覆盖检查（`roundMayClose`） | **保留并升为主判据**（P4） | 唯一可判的终止条件 |
| `adversarial record` / 覆盖协议 / gate 条件表 | **对报告式轮次保留**；**对反例补丁式轮次可大幅简化** | 报告式仍是新类发现的载体 |
| 轮协议（宿主流式、能力反驳、凭据、登记表） | **降为抽样审计的工具**（P8） | 过程级认证仍有价值，但不必施加于每次 |
| 只读/内容漂移观测 | **保留**（P3 下审查者会写，所以"限定写入范围 + 由作者裁决"取代"不许写"） | 与 P3 配套 |
| 严重度门槛 · 另一作者机制 | **保留，且应当被真正使用** | 本线实测：两者都建好但几乎未用 |
| brief 内的数字期限 | **保留** | F4 的唯一有效杠杆 |
