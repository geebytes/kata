# Align the repo's Comet install with Comet 0.4.1

`.comet/config.yaml` still used the pre-`comet.project.v1` schema: top-level `language`, `context_compression`,
`review_mode` and `auto_transition`, with no `schema:` field. Comet 0.4.1 rejects that shape, so classic artifact
layout resolution failed and every entry point reported `Comet workflow entry is unavailable because
.comet/config.yaml is missing` — including the read-only Ambient Resume probe that `AGENTS.md` asks for before
non-trivial work. `comet doctor` named the same root cause (`Classic artifact layout: unavailable from
.comet/config.yaml`, `Classic OpenSpec root: …`, `working directories: …`) while the file itself was present and
readable on disk.

The configuration is now migrated to `comet.project.v1`: `default_workflow: classic`, `workflows: [classic]`,
`ambient_resume: true`, the memory and knowledge defaults, and a `classic` section carrying the four previous values
unchanged (`language: en`, `context_compression: off`, `review_mode: standard`, `auto_transition: true`).
`classic.artifact_layout: legacy` is declared explicitly because this repository keeps its Classic artifacts in the
root-level `openspec/` rather than under `docs/openspec/`.

The managed Comet and Superpowers assets were refreshed to 0.4.1 with `comet init --yes --workflow classic
--language en --codegraph skip --scope project`: 25 tracked files modified, 3 removed and 37 new paths under
`.agents/skills/` (the `comet` family plus the refreshed superpowers set), `.opencode/skills|commands|rules`,
`.codex/rules`, `.codex/hooks.json` and `skills-lock.json`. The three removals are
`.codex/rules/comet-phase-guard.md` and `.opencode/rules/comet-phase-guard.md` (superseded by the Router Hook
runtime that `comet doctor` now reports as current) and
`.agents/skills/test-driven-development/testing-anti-patterns.md` (no longer shipped upstream). The OpenSpec
integration step of `comet init` failed for the `antigravity` platform in this environment; skills, rules and hooks
installed correctly, and the Classic root was detected from the existing `openspec/` tree.

Verification: `comet doctor` now reports ✓ for `Classic artifact layout` (legacy: configured `openspec/` present),
`Classic OpenSpec root` (`openspec/config.yaml` is valid, `spec-driven`), project-scope skills, rules, hook runtime
and hooks; `comet resume-probe` resolves the project config (`workflow: classic`, `skill: comet-classic`,
`entry_source: project-config`) instead of reporting an unavailable entry. `npm test` runs 415/416 tests green; the
single failure is `tests/unit/installer.test.ts` spawning the hardcoded path
`/home/work/.nvm/versions/node/v22.23.1/bin/node`, which this machine does not have — no test file was touched here
and the failure predates this change.

Kata itself is unaffected: `src/` is untouched, so `dist/cli.js` did not need a rebuild.
